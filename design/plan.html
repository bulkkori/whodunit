🕵️ 후더닛 (Whodunit)

3~6인 온라인 추리 보드게임 · 기획서 v1 · 2026-11-01 · 상태: v1 구현 완료 · v2 기획 중

개요① 등장하는 것② 규칙·경제③ 진행·서버④ 조작⑤ 화면⑥ 완료 기준성능 상한기술데모 배포아트 에셋v2 기획보류·제외

개요

  • 목표: 사건 봉투 속 3장(범인 · 도구 · 장소)을 가장 먼저 정확히 고발한 탐정이 승리.
  • 인원: 3~6명. 빈자리는 AI 봇으로 채울 수 있음(혼자서 봇과도 플레이 가능).
  • 오리지널 원칙: 출발 칸·문·비밀 통로·주사위 이동·추론/반박 같은 추리 보드게임 장르 공통 규칙은 쓰되, 특정 상용 게임의 보드 배치·등장인물·무기·방 구성은 따라 하지 않는다.
  • 원본 기획 대비 변경: 기존 상용 게임의 이름·캐릭터·방 구성은 쓰지 않고, 테마 3종의 인물·도구·방을 모두 새로 만듦. 맵은 고정 보드가 아니라 인원수에 따라 자동으로 생성됨.

크기 기준: 주사위 2개(평균 7칸)로 방→방이 대개 2턴. 한 번에 다른 방에 닿을 확률 3인 24% → 6인 12% (맵 300개 실측). 이동은 상하좌우만, 대각선 불가.

맵 생성: 시드값으로 결정적 생성. 보드를 3×3 구역(6인은 4×4)으로 나눠 바깥 고리에 방을 두고(네 모서리는 고정, 비밀 통로용), 정중앙은 항상 🗂️ 사건 파일실(봉투가 놓인 곳, 문 2개, 최소 4×4 — 전원 출발점). 구역 사이 2칸 복도가 전부 이어지므로 모든 문에 도달 가능 — 시드 1000개 자동 테스트로 확인.

② 규칙 · 경제 · 진행

재화·성장 없음(한 판 완결형). 대신 턴 규칙이 경제 역할.

한 턴

  1. 이동: 2d6 굴리고 그 이하 칸 이동(복도 칸 1칸 = 1, 방 입장 시 남은 이동 소멸). 모서리 방이면 대신 비밀 통로 사용 가능. 다른 말이 있는 복도 칸은 통과 불가.
  2. 추론(선택): 방 안에 있을 때만. 용의자 + 도구 + 현재 방을 지목.
  3. 반박: 시계 방향으로 지목 카드 중 하나라도 가진 첫 사람이 1장을 고르고 추론자에게만 공개. 아무도 없으면 "반박 없음" 공지.
  4. 최종 고발: 중앙 사건 파일실에 들어가야만 가능(주사위로 이동해 입장, 입장한 턴 또는 다음 턴 시작에). 3장 지정 → 봉투를 혼자 확인. 맞으면 승리·전원에게 공개, 틀리면 탈락.
  5. 사건 파일실에서는 추론 불가(장소 카드가 아님).

예외 규칙

  • 탈락자는 말이 보드에서 사라지지만 패는 비공개로 유지하고 반박은 계속 함. 봉투를 열어 봤으므로 정답을 알고 관전(채팅이 없어 누설 경로 없음).
  • 자기 캐릭터 카드를 들고 시작한다는 보장은 없음 — 자기 캐릭터가 범인일 수도 있다.
  • 변형 규칙 후보(방 옵션, v1.1): 탈락 시 패 전체 공개 — 진행이 빨라짐.
  • 추론으로 소환된 탐정 말은 다음 턴에 그 방에서 바로 추론 가능.
  • 모두 탈락하면 정답 공개, 승자 없음.

③ 진행 · 서버 · 봇

항목규칙
판정서버가 심판. 봉투·전원 패·주사위는 서버만 생성. 클라이언트는 자기 패만 받음. 모든 행동은 서버가 검증 후 반영.
턴 타이머2분. 초과 시 이동 패스 + 추리 없이 턴 종료. (반박은 15초)
잠수 처리연속 2회 초과 → 봇 전환. 본인이 아무 행동이나 하면 다시 사람으로 복귀.
반박 타이머15초. 초과 시 서버가 맞는 카드 중 무작위 1장 자동 공개.
연결 끊김60초 안에 재접속하면 자리 복구(같은 브라우저 토큰). 넘으면 봇 전환.
동기화WebSocket 이벤트 방식(폴링 없음). 상태가 바뀔 때만 전송.
정보 공개 범위공개 로그: "A가 (용의자·도구·방)을 추론 → B가 카드 1장 보여줌". 카드 내용은 추론자·반박자와 관전자(탈락자)만 봄. 봉투는 게임 끝 또는 고발에 실패한 본인에게만 공개.
봇자기 메모장에서 소거된 카드를 제외하고, 아직 모르는 후보 중 가장 가까운 방으로 이동해 추론. 각 종류 후보가 1개씩 남으면 고발. 반박 시 이미 보여준 카드 우선 공개.

④ 조작

  • 마우스/터치 공통: 주사위 버튼 → 이동 가능한 칸이 강조 → 칸 클릭으로 이동. 방은 방 아무 데나 클릭.
  • 비밀 통로: 모서리 방에 있으면 "통로 이용" 버튼 표시.
  • 추론/고발: 모달에서 카드 3장 선택(장소는 추론 시 현재 방으로 고정).
  • 메모지 드로어: 손잡이를 끌어서 슬라이드(PC는 마우스 드래그, 폰은 아래에서 위로 쓸어 올림), 탭/클릭하면 자동 슬라이드. 칸 조작은 ⑤ 참고.
  • 키보드: R 주사위, S 추론, N 메모지 열기/닫기, Esc 모달·드로어 닫기. 모달이 열려 있거나 메모 입력 중이면 단축키 무시.

⑥ 완료 기준

  • 방을 만들면 4~6자 코드가 나오고, 다른 브라우저에서 그 코드로 입장하면 양쪽 대기실에 서로 보인다
  • 배포 주소에서 서로 다른 네트워크(예: 폰 LTE + PC 와이파이)의 두 기기가 같은 코드로 한 판을 끝까지 진행할 수 있다
  • 인원 3/4/5/6으로 시작하면 그리드가 12/14/16/18, 방이 6/7/8/9개로 생성된다
  • 생성된 모든 맵에서 모든 방 문이 시작 칸에서 도달 가능하다 (시드 1000개 자동 테스트)
  • 봉투는 종류별 1장이고, 나머지 카드는 전원에게 장수 차이 1 이하로 나뉜다
  • 클라이언트가 받는 메시지 어디에도 다른 사람 패나 봉투 정보가 없다 (자동 테스트)
  • 주사위 눈보다 먼 칸이나 막힌 칸으로 이동 요청을 보내면 서버가 거부한다
  • 방 밖에서 추론 요청을 보내면 서버가 거부한다
  • 추론하면 지목된 용의자 말이 그 방으로 옮겨진다
  • 반박은 시계 방향 첫 보유자에게만 모달이 뜨고, 고른 카드는 추론자와 관전자에게만 보인다
  • 반박자가 15초 동안 고르지 않으면 맞는 카드 1장이 자동 공개된다
  • 2분 동안 아무것도 안 하면 턴이 넘어가고, 2번 연속이면 봇으로 바뀌어 다음 턴부터 혼자 진행한다
  • 게임 시작 시 모든 말이 중앙 사건 파일실에 있고, 한 번 나갔다 다시 들어오기 전에는 고발이 거부된다
  • 모서리 방에서 통로를 쓰면 주사위 없이 대각선 모서리 방으로 이동한다
  • 중앙 사건 파일실 밖에서는 최종 고발 버튼이 비활성이고, 서버도 거부한다
  • 사건 파일실에서는 추론이 거부된다
  • 틀린 고발 → 탈락·관전 화면에 봉투 정답 표시(본인만), 이후에도 반박 차례가 오면 카드를 낸다
  • 맞는 고발 → 전원에게 결과 화면과 봉투 3장이 뜬다
  • 봇 6명만으로 한 판을 돌리면 200턴 안에 반드시 끝난다 (자동 테스트 100판)
  • 게임 중 새로고침하면 같은 자리로 복귀하고 메모지 표시도 그대로다
  • 메모지 손잡이나 N키로 드로어가 슬라이드로 열리고 닫히며, 열린 상태에서도 주사위·이동이 된다
  • 손잡이를 끌다가 절반 넘은 지점에서 놓으면 끝까지 열리고, 절반 전이면 다시 닫힌다
  • 추론 창에서 메모지에 ✓한 카드 옆에 보유자 이름이 보인다
  • 메모지 칸을 탭할 때마다 빈칸 → ✗ → ✓ → ? → 빈칸 순으로 바뀐다
  • 게임 시작 시 내 패가, 반박을 받으면 그 카드가 메모지에 자동 표시된다
  • 메모지 내용은 다른 플레이어에게 전송되지 않는다 (네트워크 메시지 검사)
  • 테마 3종이 각각 다른 인물·도구·방 이름과 색으로 표시된다
  • 폰 세로(360px)에서 가로 스크롤 없이 플레이 가능하다
  • 브라우저 콘솔 에러 0건

성능 상한

최악 장면: 6인, 18×18 보드, 반박 모달이 뜨는 순간.

항목상한
보드 렌더DOM 그리드 324칸, 상태 변화 시 바뀐 칸만 갱신. 애니메이션은 말 이동 1개만 동시에(CSS transform)
메시지상태가 바뀔 때마다 각자에게 자기 시점 상태 1개, 크기 ≤ 8KB (실측: 4인 12×12에서 약 3.3KB)
서버방 상태는 메모리만(DB 없음). 서버 1대 동시 방 100개 기준
첫 로딩HTML+JS+CSS ≤ 150KB, 이미지 없이 이모지·CSS로 표현(v1)

기술

  • 언어: TypeScript (strict). 서버·공용 로직·테스트는 Node 22.18+의 타입 제거 기능으로 빌드 없이 바로 실행(node server.ts), 브라우저 코드만 esbuild로 번들. 타입 검사는 tsc(noEmit).
  • 서버 server.ts: Node.js + ws. 같은 서버가 public/ 정적 파일도 제공.
  • 클라이언트 client/: 프레임워크 없는 TypeScript → public/build/. 3D(board3d.ts, Three.js r187)는 별도 청크로 분리돼 3D를 켤 때만 로드(압축 후 약 560KB). 2D 첫 로딩 JS 약 20KB.
  • 공용 로직 shared/game.ts: 맵 생성·카드 분배·이동 검증·반박 순서·봇. 순수 함수라 서버·브라우저·테스트가 같은 코드 사용. 메시지 형식은 shared/protocol.ts로 서버·클라이언트가 공유.
  • 테스트: node --test(추가 의존성 없음). npm run check = 타입 검사 + 테스트.
  • 배포 (v1 포함): 참여 코드로 인터넷 어디서나 접속. Vercel은 상시 WebSocket 서버를 못 띄우므로 Node 서버를 Render 같은 호스트에 올림. 주소 하나 + 방 코드(또는 ?room=코드 링크)로 입장.

  5. 사건 재구성 엔딩 → 나머지 세계관(수영장·극장) 추가

보류 · 제외

  • 미스터리 이벤트 카드 — 제외. 공식 판본 하나의 무작위 효과 카드 시스템과 비슷해서. 대신 v2의 세계관 기믹·특수 방 능력으로 대체
  • 캐릭터 능력 "사기꾼"(반박 때 한 번 거짓말) — 보류. 추리 신뢰를 흔드는 강한 규칙이라 v2를 돌려 본 뒤 재검토
  • 정보 거래·잠복 토큰 — v2 이후, 정보가 부족하다고 느껴질 때
  • 랭킹·승률 프로필 — 계정·DB가 필요해서 보류
  • 채팅 — 관전자가 정답 힌트를 흘릴 수 있어 v1 제외
